# Task Contract: public-travel-from-content-repo — Public Travel pages read the content repository
- Class: **L** (cross-layer: read module + schema widening + seed + pages; no new dependency, no new secret; `security` review not required unless the owner wants one: no trust-boundary change, but public output now includes editor-authored content)
- State: **DESIGNED** — gated on (1) owner accepting ADR 0012 (`docs/adr/0012-public-travel-from-content-repository.md`, Proposed 2026-11-12) and (2) PR #41 (`feat/admin-content-cms`, ADR 0011) merging. Do not start implementation before both.
- Desired outcome / user impact: an editor's published edit to a story (and the places and reviews it embeds) appears on `/chuyen-di-choi/...`, the home page, destination pages and the sitemap on the next request; the seven existing static stories keep their URLs and content; unpublished or unknown slugs 404.
- Scope IN:
  - `src/server/content/public.ts` (`getPublicContent`, `PublicStory`, adapters `repository` and `static`, `PUBLIC_CONTENT_SOURCE`).
  - Additive schema: `storyInputSchema.plannerTemplateSlug` (nullable, default null); `destinationSlug` nullable on `storyInputSchema` and `sourceSnapshotSchema`; repository, integrity and filters updated for null.
  - Seed: `src/content/travel/static-stories.ts` (`staticStoryToInput`), fresh-store seeding, `scripts/content-seed-static.ts` + `npm run content:seed-static [--dry-run]`.
  - Public pages + home + sitemap + metadata + JSON-LD switched to the read module, `force-dynamic`, `generateStaticParams` removed, block renderer for the seven block types, published reviews/places inside a story.
  - `src/server/planner/catalog.ts` takes its story list from the read module.
- Scope OUT: `/itineraries/**`, destinations and map data, `/reviews` (video reviews), permanent tour redirects (`next.config.ts`, CLAUDE.md rule 2), on-demand `revalidatePath`/`revalidateTag` (decided against in ADR 0012 decision 4; no hooks in `src/app/api/**`), a `status` on places, draft preview, `seo.canonicalPath`/`keywords`, a content PostgreSQL store, any new dependency.
- Evidence: `src/content/types.ts`, `src/content/stories.ts` (7 stories, 2 with `destinationSlugs: []`), `src/content/travel/seed.ts` (`seedTravelContent`, guard "no places"), `src/server/content/{schemas,repository,store,instance}.ts`, `src/server/persistence/json-store.ts` (process cache, one writer), `src/app/[locale]/stories/[slug]/page.tsx` (`revalidate = 60`, `generateStaticParams`), `src/app/[locale]/destinations/[slug]/page.tsx`, `src/app/[locale]/page.tsx`, `src/components/sections/hero.tsx` (imports `stories`; usage to verify), `src/app/sitemap.ts`, `src/lib/metadata.ts`, `src/server/planner/catalog.ts` (`siteStories`), `Dockerfile` (build seeds `.data/`), `docs/adr/0011-admin-content-cms.md` (implementation notes), `docs/adr/0009-postgres-persistence.md`.
- Constraints / dependencies: VI unprefixed, every string in both catalogues (`messages/vi.json`, `en.json`); no change to `src/i18n/routing.ts`; one `<h1>`, block headings `h2`/`h3` only; no `href="#"`; `PublicContent` is the only way pages obtain Travel content (pages must not import `repository.ts`/`store.ts`); single-instance assumption for the JSON content store.
- Architecture decision / ADR: ADR 0012 (Proposed). Supersedes ADR 0011 decision 8 on acceptance.
- Interface contract: `getPublicContent(): Promise<PublicContent>` with `listStories()`, `getStory(slug) -> PublicStory | null`, `listStoriesForDestination(slug)`, `listSitemapEntries() -> { slug, updatedAt }[]`; `PublicStory` fields and mapping table in ADR 0012 decision 2. `PUBLIC_CONTENT_SOURCE = repository | static`, read per request, default `repository`. Store error -> HTTP 500, never a silent fallback.
- Tasks by owner:
  - Architect: ADR 0012 (done); on acceptance flip status, update `docs/architecture.*`, `.claude/context/project-context.md`.
  - **backend-engineer (first):** `src/server/content/{public,schemas,repository,instance}.ts`, `src/content/travel/**`, `scripts/content-seed-static.ts`, `package.json` (script only), `src/server/planner/catalog.ts`, `Dockerfile` (drop the build-time `.data/` seed step if no longer needed), `deploy/**` (env var), `docs/usage.*` (flag, seed script, build page count), backend tests below.
  - **frontend-engineer (after the `public.ts` signature is merged):** `src/app/[locale]/page.tsx`, `src/app/[locale]/stories/**`, `src/app/[locale]/destinations/**`, `src/app/sitemap.ts`, `src/components/**` (cards, sections, hero, new story block renderer, admin story form null-destination handling and the "edits appear on the public site" notice from ADR 0011), `messages/*.json`, frontend tests below.
  - QC / Security / Git: on request only.
- File ownership (disjoint): backend owns `src/server/**`, `src/content/**`, `scripts/**`, `package.json`, `Dockerfile`, `deploy/**`, `docs/usage.*`, `tests/` files named below as backend. Frontend owns `src/app/**` (pages, sitemap), `src/components/**`, `messages/**`, `docs/features/public-travel-cms.*`, `tests/` files named below as frontend. No file appears in both lists; the admin story form is `src/components/admin/**` (frontend) and consumes the widened schema only through the API.
- Acceptance criteria / tests (add; do not rewrite existing ones):
  - Backend `tests/public-content.test.ts`: draft, archived, unknown slug -> `getStory` null; `listStories` published only, newest `publishedAt` first, slug tiebreak; a place used only by a draft story is not returned; unpublished review never in `reviews`; missing place slug omitted, not thrown; `plannerTemplateSlug` null when the template is private or missing; `noindex` story absent from `listSitemapEntries`; a store error rejects (no fallback); `PUBLIC_CONTENT_SOURCE=static` serves the 7 static stories and switches without a rebuild.
  - Backend `tests/static-story-seed.test.ts`: `staticStoryToInput` yields a schema-valid `StoryCreateInput` for all 7 stories; vi/en paragraph counts match; the two destination-less stories validate with null; `di-da-lat-lan-thu-sau` keeps `plannerTemplateSlug`; seeding twice creates nothing the second time; an edited seeded story is **not** overwritten; `--dry-run` writes nothing; boot does not recreate a deleted seeded story.
  - Backend: extend `tests/travel-content-schemas.test.ts` (nullable `destinationSlug`, `plannerTemplateSlug`, old documents still parse) and `tests/travel-content-repository.test.ts` (null destination in filters, template snapshot, integrity).
  - Frontend `tests/public-travel-pages.test.ts` (or extend `tests/content.test.ts`): story page 404s for an unpublished slug; sitemap lists only published, non-noindex stories with `lastModified`; `generateMetadata` returns `{}`-safe for null; JSON-LD has `dateModified`; no page module imports `repository.ts`/`store.ts` (extend `tests/client-boundary.test.ts` by adding a case); story page, destination page and home declare `dynamic = 'force-dynamic'` and none exports `generateStaticParams` or `revalidate`; `tests/i18n.test.ts` passes for new strings; block renderer renders all 7 block types with one `h1` only.
  - Whole suite: `npm run typecheck`, `lint`, `test`, `build` (build must pass with **no** `.data/` and no database); output stated; `tests/docs.test.ts` passes.
- Security and migration risks: no auth change. Data migration is additive (nullable fields, seed script). Risks: seed script recreating a deleted story when run by hand; approximate `travelDates` on six stories (rule 8, flag to owner); a store outage now takes down story pages and the home page (500, by design); per-request read cost unmeasured; two app instances will diverge on content until the PostgreSQL content store exists; `src/content/stories.ts` edits become inert.
- Reviews: `qc` recommended (M and above; mapping, 404 and seed idempotency are easy to get subtly wrong). `security` optional. Both user-invoked; report NOT RUN until called. Max two review/fix cycles, then escalate.
- Rollback approach: set `PUBLIC_CONTENT_SOURCE=static` and restart (no rebuild); or revert the PR. Seeded rows and the two nullable schema fields are harmless to leave. Static adapter and flag stay for at least one release.
- Budget: backend 1 invocation + 1 fix; frontend 1 + 1; qc 1 on request. Stop on BLOCKED or when an open question below changes the mapping.
- Feature document owner: **frontend-engineer** writes `docs/features/public-travel-cms.md` + `.vi.md` (seven sections), registered in `docs/features/README.*`; backend supplies the seed/flag facts in a PR comment.
- Architecture/usage doc updates needed: `docs/architecture.md` + `.vi.md` (architect, on acceptance: route/caching table, Phase 07 backlog line "public pages read the typed seed", module boundary for `public.ts`); `docs/usage.md` + `.vi.md` (backend: `PUBLIC_CONTENT_SOURCE`, `npm run content:seed-static`, build page count change, Docker build without a seeded `.data/`); `docs/travel-content-api.*` unchanged; `.claude/context/project-context.md` (architect).
- Open questions for the owner (block mapping details): default `PUBLIC_CONTENT_SOURCE` at cutover; `travelDates` approximation; nullable `destinationSlug`; place `status`; written reviews on `/reviews`; `canonicalPath`/`keywords`; draft preview; instance count and content-PostgreSQL timing; recreated-deleted-story tolerance. See ADR 0012 Follow-up.
