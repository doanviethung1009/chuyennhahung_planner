# Task Contract: P07-6 Template CMS (CORE-5)
- Class: **L** (API handlers move from token-only to session; repository change shared with Phase 10 content layer) · Branch: `feat/admin-template-cms` · Depends on: P07-10, P07-15 (done, PR #168), owner decisions W11 and W4 (2026-11-18) · Index: [core-completion-index.md](core-completion-index.md)
- Desired outcome: editors maintain itinerary templates in the browser (what is `curl`-only today), safely: no silent overwrite, no effect on trips already created from a template.
- Owner decisions in force: **W4 — no version history**; overwrite protection by `If-Match` only. **W11 — handlers move to session access.** Data-protection principle (owner, 2026-11-19, collections DELETE): permanent delete is not an editor action, so **template DELETE stays token-only**.
- Scope IN:
  - Pages: `/admin/content/templates` (`/quan-tri/noi-dung/lich-trinh-mau`) list with search/sort (reuse `list-utils.ts`); `/admin/content/templates/[slug]` (`/quan-tri/noi-dung/lich-trinh-mau/[slug]`) editor.
  - Editor: edit `title`, `summary`, `groupSize` (vi/en side by side), `travelStyle`, `pace`, `itinerarySlugs`, `visibility` (public/private); edit days and activities (title, summary, place, start time, duration, estimated cost, note); reorder activities inside a day and move an activity to another day with the existing `reorder` and `move-activity` endpoints (they keep activity ids); show the read-only source snapshot (`sourceSnapshot`, with a stale hint when the source story's `updatedAt` is newer than `storyUpdatedAt`) and derived fields (duration, places, total cost, `version`).
  - API (access guard + stamp only): the handlers `templates/route.ts` (GET), `templates/[slug]/route.ts` (GET, PATCH), `templates/[slug]/reorder/route.ts`, `templates/[slug]/move-activity/route.ts` move from `adminRoute` to `adminContentRoute(request, { action: 'template:write', session: true }, …)` (same pattern as `stories/route.ts`, ADR 0011 §1). The service token keeps working for the same action.
  - Overwrite protection: add optional `expectedUpdatedAt` to `updateTemplate`, `reorderActivities` and `moveActivity` in `src/server/content/repository.ts` using the existing `checkStamp`, and pass `ifMatchStamp(request)` from the three mutating handlers. Absent header stays last-write-wins for API callers; the UI always sends it and shows the 412 message. This is the same optional-parameter addition made for collections; touch only these three methods.
  - i18n VI/EN, `src/i18n/routing.ts` paths, sidebar entry, docs.
- Scope OUT:
  - **Template DELETE** (stays token-only `adminRoute`, unchanged) and **template create** (`POST /api/admin/travel/templates` stays token-only; creating a template from a story in the UI is a separate decision — list it as a follow-up in the handoff, do not build it).
  - Any version history or restore (W4), new routes, schema changes, changes to `sourceSnapshot` (immutable by design), public template pages, planner/trip code, Story and Place API.
- Evidence: `src/app/api/admin/travel/templates/**` (all token-only via `adminRoute`, checked 2026-11-19); `src/server/content/repository.ts` (`updateTemplate` ~864, `reorderActivities`, `moveActivity`, `deleteTemplate` ~1017, `checkStamp` ~1151); `src/server/content/schemas.ts` (`templateInputSchema`, `templateUpdateSchema`, `version` field); `src/server/planner/permissions.ts` (`template:write` is an editor action); `tests/planner-clone-independence.test.ts` (trips cloned from a template are frozen copies); ADR 0001 §4, ADR 0011 §1, ADR 0005; the CORE-4 handoff and `collection-editor.tsx` as the closest pattern.
- Constraints: `PATCH` with `days` replaces the day list and **re-issues activity ids** (repository comment): the UI must use `reorder`/`move-activity` for ordering and send `days` only when content of activities changed; publishing a template (`visibility: public`) requires its source story to be published (server returns `invalid_state`, show a clear message); the planner never reads a template after cloning, so editing a template must not change existing trips (keep `planner-clone-independence` green).
- Architecture decision / ADR: none new (ADR 0011 §1 covers the pattern; W4 is recorded in the index). Update `docs/architecture.*` and `docs/travel-content-api.*` (route/auth matrix changes) in both languages (rule 10).
- Interface contract: no new endpoints. Behaviour change: the 4 handlers above accept a session with `template:write`; the 3 mutating ones honour an optional `If-Match: "<updatedAt>"` and answer 412 (`stale_content`) on mismatch.
- Tasks by owner: Architect (this contract) · BE: handler guards, `expectedUpdatedAt` on 3 repository methods, tests · FE: pages, editor, helpers, routing, messages, feature doc · QC / Security: on demand · Git: main session after owner authorization.
- File ownership: BE — the 4 handler files, `src/server/content/repository.ts` (three methods only), `tests/admin-content-session.test.ts` (extend), repository tests. FE — `src/app/(admin)/[locale]/admin/content/templates/**`, `src/components/admin/content/template-*.tsx|ts`, `list-utils.ts` (only if reuse needs it), `src/i18n/routing.ts`, sidebar, `messages/*.json`, `docs/features/admin-content-templates.*`, `docs/features/README.*`. Order: backend first, then frontend; commit per role. Do not touch `src/server/planner/**`, Story/Place/Collection handlers or `templates/route.ts` POST and `[slug]` DELETE.
- Acceptance / tests:
  - Editor can list and open templates and edit metadata, days and activities, reorder and move; 412 is shown on a stale write; publishing with an unpublished source story shows the server message; `sourceSnapshot` and derived fields are read-only.
  - Handlers: no credentials → 401; editor, admin, super_admin session → allowed for the 4 handlers; member → refused; service token still works; cross-site mutation refused. **Editor/admin/super_admin sessions are refused on template DELETE and on template POST (still 401)**; token still deletes a private template, a public one stays blocked (existing rule).
  - `If-Match`: match, mismatch (412) and absent header for `updateTemplate`, `reorderActivities`, `moveActivity`, in the repository tests and via a route test; a mutation test showing DELETE reverted to `adminContentRoute` makes a test fail (as done for collections).
  - Pure helper tests (list search/sort, day/activity edit helpers, stale-snapshot check); role matrix for both pages; i18n VI/EN parity; `planner-clone-independence` and the `travel-content-*`, `admin-*` suites unchanged and green.
  - `typecheck`, `lint`, `test`, `build` output stated; browser smoke 375/768/1280 with an admin login if possible, otherwise NOT RUN (never type a password).
- Security and migration risks: trust boundary moves (token-only → session) for template read/update/reorder/move: every editor session can now change public template content — same exposure as stories and places; `/sec-check` strongly recommended before merge (owner calls it). No DB migration (templates live in the content store; PostgreSQL goes through the same repository).
- Rollback approach: revert the PR; `expectedUpdatedAt` is an optional parameter, so older callers are unaffected.
- Budget: sub-agents 0. Stop and ask the owner if: the repository change needs more than the three methods, a schema change seems necessary, or the template editor cannot be built without a new endpoint.
