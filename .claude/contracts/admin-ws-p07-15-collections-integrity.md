## Amendment 2026-11-18 (W11) — handlers move to session access
- **Handlers changed (access guard only, bodies untouched):** `src/app/api/admin/travel/collections/route.ts` (GET, POST), `collections/[slug]/route.ts` (GET, PUT/PATCH, DELETE as present), `collections/[slug]/status/route.ts`, `src/app/api/admin/travel/integrity/route.ts`: replace `adminRoute(request, …)` with `adminContentRoute(request, { action: 'content:write', session: true }, …)` (same pattern as `stories/route.ts`, ADR 0011 §1). The service token keeps working (`resolveAdminPrincipal` still accepts it for the same action).
- **Planner integrity:** `src/app/api/admin/planner/integrity/route.ts` currently calls `adminPlannerRoute(request, handler)`, which defaults to `{ action: 'user:provision' }` without `session`. Pass `{ action: 'user:provision', session: true }` so an admin browser session can read it; editors stay refused. The response keeps identifiers and issue text only, no trip content (ADR 0002 §3 unchanged).
- **Templates are NOT moved here.** `templates/**` handlers stay token-only until CORE-5 (P07-6); do not touch them.
- **Collection create/delete:** the create (`POST`) handler moves with the rest; whether the UI offers create/delete is the implementer's call inside this scope — if offered, delete needs the same confirm pattern as P07-16 archive; if in doubt, ship list + edit + status only and note it in the handoff.
- **Mutations:** session mutations inherit the same-origin check and the 30/min per-user limiter (ADR 0010 §8) from `resolveAdminPrincipal`; do not add a second limiter. `If-Match` on update stays optional on the API and is always sent by the UI.
- **Extra tests (backend):** for every moved handler: no credentials → 401; editor session → 200 for content routes; member session → 403/404 as the helper returns; service token still 200; cross-site request refused for mutations; planner integrity: editor session refused, admin session 200. Extend `tests/admin-content-session.test.ts` (route/action matrix) rather than a new harness. Existing `travel-content-*` and `admin-*` suites stay green.
- **Security:** a trust boundary moves (token-only → session). `/sec-check` is **recommended before merge** (user calls it). Residual risk to state in the handoff: collections are now writable by every editor session — same exposure as stories and places.
- **ADR:** no new ADR; ADR 0011 §1 covers the pattern. Record the moved routes in `docs/features/admin-content-collections.*` and, because the route/auth matrix changes, in `docs/architecture.*` and `docs/travel-content-api.*` (rule 10).
- **Ownership order:** backend role (handlers + tests) first, then frontend role (pages, `content-list.tsx` search/sort, routing, messages, feature doc). One session, one branch, one PR; commit per role.

## Amendment 2 (2026-11-18) — `If-Match` on collections PATCH
- Why: the W11 amendment assumed the collections PATCH honours `If-Match`, but `updateCollection` has no stamp check and the handler ignores the header, so the UI's 412 criterion could not be met. Owner chose option A ("Chọn A").
- Change (API-behaviour addition limited to an optional parameter): `src/server/content/repository.ts` — `updateCollection(slug, patch, expectedUpdatedAt?)` calls `checkStamp('collection', …)` inside the transaction (that method only; the one repository class serves both the JSON and PostgreSQL stores); `src/app/api/admin/travel/collections/[slug]/route.ts` PATCH passes `ifMatchStamp(request)`.
- Absent header stays last-write-wins for API callers; empty header is 400; stale is 412 `version_conflict`. No new route, field or schema change.
- Tests: match, mismatch (412, nothing written), absent header, in `tests/admin-content-session.test.ts`.
- `place_in_use` stays OUT of scope.

## Decision 2026-11-19 — collection DELETE stays token-only (data protection, owner)
- After `/sec-check` W1 (editor-reachable permanent delete, inconsistent with stories and places) the owner chose: keep `DELETE collections/[slug]` on the token-only `adminRoute`. GET, POST, PATCH and status stay on session access (`content:write`). Story and place DELETE unchanged. The UI offers no delete.
- Long-term model (Archive → Restore → Permanent Delete by `super_admin`) is a separate backlog row, ID to be assigned by the owner; not in this PR.
