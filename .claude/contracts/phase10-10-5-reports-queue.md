# Task Contract 10.5 — Report Content + Admin Moderation Queue
- Task ID: P10-3
- Class: L (new anonymous write path + personal data) · State: READY (owner approved D1-D12 as recommended, 2026-11-16) · Subagents: 0
- Objective: any reader can report a published community trip or review; staff see and resolve reports in the admin portal; every resolution is logged.
- Scope:
  - Table `reports`, `db/migrations/0013_reports.sql` + rollback, JSON key `reports`; fields per `docs/specs-community-database.md`: `id`, `reporterId|null`, `clientKey`, `targetKind` (`trip|review`), `targetId`, `reason` (fixed list: spam, harassment, personal data, copyright, misleading, other), `note` ≤500, `status` open/actioned/dismissed, handler fields; index `(status, created_at)`.
  - `POST /api/community/reports` (guest or signed-in), limited by the 10.3 async limiter (10/day, `docs/specs-community-api.md` §limits), duplicate open report by the same reporter on the same target ignored (still 2xx, no leak).
  - Admin: `GET /api/admin/community/reports?status=` and `POST …/reports/[id]/resolve {outcome: dismissed|actioned, reason}` (`community:moderate`); `actioned` marks the report only — removal stays the existing remove actions. Resolve writes an audit event (10.2 helper).
  - UI: Report control on community trip card/page and on each review; admin tab listing reports beside the existing queues (`src/components/admin/community/`, `src/app/[locale]/admin/community/page.tsx`).
  - D7: reviews need an opaque non-personal `id` in `PublicCommunityReview` (`schemas.ts:894-902`); the trip target is resolved from the public `shareToken` to the trip id server-side (never stored).
- Out of Scope: auto-hide by report count (comments only, Phase 14), reporter notifications, appeals, comments/journals as targets, `moderator` role, restriction from the report screen.
- Architecture Reference: `docs/specs-community-moderation.md` §Reported content; `…-api.md` rows for reports; `…-security.md` (report abuse); ADR 0014/0015.
- Dependencies: 10.2 (events, helper), 10.3 (async limiter) both merged; soft 10.4. Owner D7.
- API/Data Contract: request `{ targetKind, targetId|shareToken, reason, note? }` → `201 {ok:true}` (also for deduplicated); staff list shape contains no `clientKey`/reporter id beyond a staff-needed flag (`signedIn: boolean`); guest `clientKey` stored hashed, never returned.
- Files Affected: `db/migrations/0013_*`, `db/rollback/0013_*`, `src/server/planner/{schemas,store,repository}.ts`, `src/server/persistence/{planner-rows,planner-transfer}.ts`, `tests/planner-pg-fixtures.ts`, `src/app/api/community/reports/route.ts` (new), `src/app/api/admin/community/reports/route.ts` + `[id]/resolve/route.ts` (new), `src/components/**` (report button/dialog, admin reports list), `src/app/[locale]/admin/community/page.tsx`, `src/app/[locale]/community-trips/page.tsx`, `src/components/reviews/**`, `messages/*.json`, tests, `docs/features/community-reports.md` + `.vi.md`, `docs/features/README.*`, `docs/architecture.*`, `docs/specs-community-database.*`.
- FE/BE Responsibilities: BE first (contract settled in the first commit), then FE in the same PR; BE writes the feature document `community-reports` (7 sections, both languages). FE: accessible dialog (focus trap, real buttons, ≥44px), VI/EN strings, no `href="#"`.
- QC Requirements: report succeeds for guest and member; unknown or non-public target → `404`/`invalid_reference` with no existence leak; duplicates ignored; over the daily limit → 429 `Retry-After`; DB down → 503, nothing stored; resolve requires `community:moderate` (member 403, editor ok); resolve twice is idempotent; one event per resolve; public projection tests updated **only** for the added `id` (listed in the PR); both stores; i18n parity; a11y.
- Security Requirements: anonymous write path → shared limiter + honeypot pattern as guest reviews; note is plain text, length-capped, escaped on render, never logged; `clientKey` hashed (HMAC arrives in 10.6b — keep one helper); staff cannot see reporter identity; recommend `/sec-check` (anonymous write, personal data in notes) — NOT RUN until called.
- Acceptance Criteria: QC list passes; a report of a removed item no longer appears actionable; no other public field changes.
- Verification Commands: `npm run typecheck`, `npm run lint`, `npm run test`; Postgres cases with `TEST_DATABASE_URL`; viewport check at 375/768/1280 for the new controls.
- Rollback Strategy: remove the control and routes; rollback SQL drops `reports`; stored rows inert; the added review `id` is harmless to leave.
- Definition of Done: criteria met, outputs stated, docs in the same PR, handoff `phase10-10.5.md`.
