- Scope IN:
  1. `@playwright/test` as a dev dependency (exact version at least two weeks old; state it), `playwright.config.ts`, a new folder `e2e/` (NOT under `tests/`: vitest keeps `include: tests/**/*.test.ts` unchanged), script `npm run e2e` (+ `npm run e2e:ui` optional), `.gitignore` for `.data/e2e/`, `test-results/`, `playwright-report/`.
  2. **Server under test:** the production build (`npm run build` then `next start`) on a free port, started by `webServer` with a **throwaway data directory** (`PLANNER_STORE` and `TRAVEL_CONTENT_STORE` pointing into `.data/e2e/<run-id>/`, names verified in `docs/usage.md`), `ADMIN_API_TOKEN`, `GUEST_KEY_SECRET` and the session secrets **generated per run** with `crypto.randomBytes` (never committed, never printed). If a throwaway PostgreSQL is selected (`E2E_DB=postgres`), use `PLANNER_DATABASE_URL`/`CONTENT_DATABASE_URL` for a database whose name contains `e2e` or `test`.
  3. **Safety guard in `globalSetup`** (hard fail, tested): refuse to run when `baseURL` is not `localhost`/`127.0.0.1`; refuse when a database URL is set whose host is not local or whose database name does not contain `e2e`/`test`; refuse when `E2E_*` env points at the dev VM address. No override flag.
  4. **Accounts:** created by `globalSetup` through the app's own paths — the service token `POST /api/admin/planner/users` (as CORE-8 did) or `createAdminAccount` — with passwords generated per run; the temporary-password gate for staff roles is exercised as a real step (change password), not bypassed. Roles needed: member, editor, admin, super_admin. No real or reused password anywhere; storage state files live in `.data/e2e/` and are git-ignored.
  5. **Specs, tagged `@smoke`, v1 target ≤ 14 tests, one `<h1>` and no horizontal overflow asserted where noted:**
     - Public pages, VI and EN subset, at 375/768/1280: home, stories, a story, destinations, places list (`/dia-diem` search "da lat" and "Đà Lạt" return the same set), a place page, `/trip-templates`, `/plan-your-trip` (links `/stories`, `/my-trips/new`, contact routes), map; no `href="#"`.
     - Redirects: `/tour`, `/tours`, `/tour/x`, `/tours/x` → 308 `/len-lich-trinh…` (rule 2).
     - Flow A: sign in (member) → create a trip from `/trip-setup/<template>` → editor: add activity and expense, reorder → share `unlisted` → open `/chia-se/<token>` in a fresh context signed out: 200, `noindex`, no analytics requests; wrong token 404; archive revokes the link.
     - Flow B: guest review on a place; member without accepted Terms is refused (403 `terms_not_accepted`), accepts, then posts; add a place to a trip.
     - Flow C: member lists a trip → admin approves in `/admin/community` → appears at `/community-trips` → guest reports it → admin resolves and removes → events visible at `/admin/audit`.
     - Flow D (admin): role matrix pages (editor gets 404 on `/admin/system` and `/admin/audit`; super admin 200); story create with slug auto-fill and preview; place edit with a **two-context `If-Match` conflict** (412 message and reload); template reorder and publish refusal when the source story is unpublished; **DELETE collection/template/place with a session is refused** (API).
     - Flow E: sign-in / sign-out, password change mismatch and success, `returnTo` guard (open-redirect refused).
     - Member map (after #210): `/my-map` guest sees no data; member sees own points only; enable share link, open `/shared-map/<token>` signed out (public projection, `noindex`), revoke → 404.

## Open questions (answered above; kept for the record, recommendation first)
- **Q1. Run E2E in CI on every PR?** Recommend: yes, as a separate advisory job with a `paths` filter and on `push` to `main`; cost about one extra job of several minutes per relevant PR. Alternative: nightly and manual only.
- **Q2. JSON store or PostgreSQL in CI?** Recommend: JSON store for v1 (fast, isolated per run); add a second job on the existing Postgres service later, once flows are stable. Decision 9 allows both.
- **Q3. Browsers:** recommend Chromium only (Chrome locally via `channel: 'chrome'`); Firefox and WebKit later if wanted.
- **Q4. Locale coverage:** recommend VI for every flow and EN only for the public-pages subset and `/plan-your-trip`.
- **Q5. Allow downloading Chromium on the developer machine?** Recommend: no, use the installed Chrome; the CI downloads its own. Say yes only if no local Chrome.
- **Q6. May the suite add `data-testid` to product code where no accessible role or label is stable?** Recommend: no in v1; report the gap instead.
- **Q7. Start now or after PR #210?** Recommend: after #210 merges (the My Trips and My Map specs depend on it).
